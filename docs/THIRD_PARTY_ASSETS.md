## Follow-up: rapid FPS adaptation and CC0 building photographs (October 2026)

Production browser measurements on the previous build confirmed actual WASD movement but average 12.98 FPS on a constrained Cloudflare screenshot browser; CI software-rendered Chromium measured 15.06 FPS (desktop-low), 33.89 FPS (mobile emulation-low) and 15.31 FPS (desktop balanced), under non-comparable emulated renderer conditions. These were real frame samples, not synthetic guessed numbers. The player-position tests use actual keys/touch coupled to the real game simulation, with an explicit `?qa=1` test-only fixed-step path so software GPU starvation does not get mistaken for a control failure.

The next optimization lowers the adaptive-resolution response interval from 3 seconds to 0.85 seconds and drops rendering scale more aggressively if measured FPS is deficient; all quality selection remains available and stronger GPUs retain their resolution. The material atlas additionally draws a locally-bundled CC0 photographic `ambientCG Bricks066` masonry tile alongside `Grass004` and `Ground037`. Exact license and source path are in `browser/3d/assets/materials/MANIFEST.json`; diffuse color is photographic while bump/roughness are approximate, and limestone remains authored/generated. This is realism improvement, **not** photorealistic AAA or a verified 60 FPS target.


## Browser realism, movement and measured playtesting (October 2026)

**Actually implemented:** The 3D browser edition supports WASD, arrow keys, mouse aim/fire, pointer-lock on deploy, mobile dual-touch sticks, crouch and sprint. A former 45-millisecond-per-rendered-frame simulation cap meant slow GPUs slowed in-game time; it now uses bounded wall-clock substeps. The new `telemetry.js` reports actual frame timings (average FPS, 1%-low, frame p50/p95/p99, CPU render time), player meters traveled/stuck time, firing/accuracy, captures and kills. Press **F3** during gameplay to view measurements and export JSON; nothing is uploaded.

**Photographic CC0 terrain:** Two self-hosted 256-pixel albedo photographs from ambientCG (`Grass004`, `Ground037`) augment the terrain's shader atlas; the stone/brick surfaces and normal/roughness maps are still procedural/approximated. Creator/license/original source recorded in `browser/3d/assets/materials/MANIFEST.json`. No image CDN is required and photo loading failures preserve the existing atlas. Low-tier lighting and skinned actor detail are reduced to maintain input responsiveness.

**Automated real gameplay benchmark:** `.github/workflows/browser-playwright.yml` runs a pinned Chromium on a public-repo standard hosted Linux runner, serves the Cloudflare static assets locally, actually moves the player using keys/touch, fires/commands the squad, captures runtime errors, and saves screenshots plus measured frame-time JSON/Markdown in Actions artifacts. Unlike mock tests this runs a real browser, but **GitHub's headless SwiftShader/software renderer FPS must not be extrapolated to real gaming GPUs or phones**. Test browser/mobile resolutions and regression reports are representative only of those specific emulated contexts. Tests are strict: no invented FPS values and no pass if the avatar never moves. If the browser is too slow to simulate a movement interval in time, this is a failure that must be investigated.

**Open work for photorealism:** Replace remaining stylized low-poly CC0 meshes with historically correct WWII models/rigs/mocap, scanned calibrated PBR surface sets at device-appropriate resolution, better lighting/shadows, advanced terrain/foliage shaders and LOD/instancing. Test manually and record genuine frame times on multiple actual devices. The free Cloudflare platform serves files; end-user GPUs determine render speed. Public Actions standard hosted runners are free within GitHub policies, not unlimited by guarantee.


## Real glTF skeletal rig + local PBR material atlas (October 2026)

The Cloudflare `/3d/` game now uses a **real skinned Kenney CC0 humanoid model** on nearby soldiers: 58 joints with inverse bind matrices, weighted vertex influences, hierarchical transforms, and gait/crouch poses. The implementation (`browser/3d/skinning.js`) also interprets simple LINEAR/STEP glTF animation channels when supplied. **This particular Kenney GLB contains no animation clips**; its poses are generated by our bone animation code. Near soldiers use the rigged mesh according to a graphics-tier cap, while farther soldiers or failed downloads use the established optimized original infantry geometry. A period-inspired helmet, webbing, packs and rifle are overlaid. The source character is a stylized survivor, not a faithful British or German 1944 uniform. Its content and exact original Git SHA1/SHA256 are pinned in `browser/3d/assets/kenney/CHARACTER_MANIFEST.json`.

**Texture pipeline:** the WebGL2 shader samples a locally generated **4-material atlas** (pasture, mud, limestone and brick) with albedo, tangent-like bump normal and roughness channels, rather than only flat material colors. Its source is `browser/3d/material-atlas.js`; the same shader has a low-tier fallback that bypasses atlas calculations for limited phones. The atlas is deterministic and generated on-device with no network. **These are not professionally photographed ambientCG PBR maps**; real measured/photographic material capture and physically accurate tangents remain separate future work.

**Recorded audio:** an optional small `cc0-gunshot.wav.b64` from `transitive-bullshit/ai-safety-doom` was composed from documented CC0 shotgun/airsoft pump recordings; its original creators and source are tracked in `browser/3d/assets/audio/MANIFEST.json`. Audio decoding occurs after deployment; failed downloads or WebAudio decoding simply keep the synthetic spatial sound. This is a **generic recorded gunshot layer, not authentic period Lee-Enfield/Sten/Bren recordings**. No third-party runtime service is needed.

**Regressions:** `browser_skinning_smoke.js`, `browser_material_atlas_smoke.js`, `browser_recorded_audio_smoke.js`, and the combined scene test cover source integrity, actual vertex deformation, texture upload and fallback. For full production realism we still need dedicated WWII meshes, detailed character texture assets and authentic animations/audio, material artist review, physical device profiling and graphical quality assurance.


## Tactical presentation and CC0 Quaternius farm update (October 2026)

The Cloudflare game now includes a period-informed **3D infantry and weapon presentation layer** (`browser/3d/battle-art.js`) and a new **spatial WebAudio sound engine** (`browser/3d/battle-audio.js`). Infantry visual poses vary with movement, direction, suppression and crouching, and three separately shaped first-person weapons distinguish the Lee-Enfield, Sten and Bren. Sounds are *original procedural synthesis* (weapon report, battlefield wind, distant fire, footsteps and nearby artillery); they are **not professionally recorded sound samples**. Audio starts only after deployment and has a mute control. Procedural terrain shading adds grass, masonry and brick variation plus atmospheric fog; it is **not a full PBR texture pipeline**.

**Genuine additional CC0 art:** 4 Quaternius Farm Buildings models (barn, chicken coop, windmill, well) are bundled alongside the existing 5 Kenney Nature models. The Quaternius GLBs are placed in the actual Normandy map, have simplified physical collision and line-of-sight occlusion, and are not fetched from a third party at runtime. Farm asset failure preserves the Kenney world; total asset failure preserves the original procedural level. The `browser/3d/assets/quaternius/MANIFEST.json` file pins license, creator, source SHA-256 and Git blob identities.

**Licensing:** Kenney and Quaternius source assets are CC0; all new authored game geometry and procedural sound code are original. No restricted Fab, Sonniss or questionable Sketchfab media is distributed. Inspect all attribution/provenance entries before public distribution.

**Still not shipped:** skinned and retargeted imported WWII character meshes and motion-captured clips; authentic licensed weapon meshes; photo-based terrain PBR normal/roughness/albedo maps; recorded cinematic explosions and Foley. These require a texture-capable glTF/skinning loader, source-file clearance, size optimization, and real-device QA. These should not be described as complete.

Tests: `node tools/tests/browser_visual_audio_smoke.js`, `node tools/tests/browser_quaternius_glb_smoke.js`, and `node tools/tests/browser_cc0_scene_smoke.js`.

## Self-hosted Cloudflare browser scenery — Kenney CC0

The browser `/3d/` edition now vendors five original **Kenney Nature Kit v2.1** meshes (oak, pine, rock, bush and fence) as canonical Base64-encoded GLB files under `browser/3d/assets/kenney/`. They are decoded on the device and embedded into existing WebGL2 static geometry. Credit is optional under **CC0 1.0**, but we preserve it:

- Original publisher and license: https://kenney.nl/assets/nature-kit
- Public redistribution mirror: https://github.com/Hidencod/tge-assets
- Immutable per-file upstream Git blob hashes, byte lengths and exact paths: `browser/3d/assets/kenney/MANIFEST.json`
- Integrity test: `node tools/tests/browser_cc0_glb_smoke.js`
- Integration/fallback test: `node tools/tests/browser_cc0_scene_smoke.js`

This distinct browser source register complements the Unreal `ExternalAssets/asset-lock.json`; nothing from Fab, Sonniss, or unclear-license Sketchfab uploads has been vendored. The current geometry importer supports only static triangle meshes and uniform color materials, not skinned soldiers, weapon animations or photorealistic PBR textures.

## Rule

A resource being "free" is not sufficient. Every asset integrated into the project must have:

1. a source URL;
2. a recorded license/provider terms;
3. an acquisition date/version where possible;
4. a known redistribution policy;
5. a project destination;
6. a documented gameplay/presentation purpose.

If any of these are unknown, the asset remains unapproved.
